# RAPOMAN manga publishing pipeline

## 目的
ChatGPT等の執筆AIを信用してそのまま公開しない。RAPOMAN漫画記事は、固定ルール・機械監査・独立AI監査の2段階ゲートを通過した記事だけ自動公開する。

## 固定ルール
`rules-v1.json` が正本。主な原則:

- ユーザー本人の独自感想・本音・変な着眼点が主役。
- AIは王道ポイント、事実、背景、抜け漏れをネット調査して補完する脇役。
- AIがユーザーの意見を捏造・上書きしない。
- タイトル → パッション導入 → コミックス書影 → 更新日時点の最新情報 → 基本情報・あらすじ → 可変数のパッション章、の順。
- 点数、星評価、おすすめ度、こんな人におすすめ、メリット・デメリットは禁止。
- 原作引用画像は改変不可。引用条件が怪しければオリジナル画像へフォールバック。
- 海外版も同じ構成を維持する。

## 投稿データ
`post.template.json` を雛形に `post.json` を生成する。

`post.json` には本文だけでなく以下を必須メタデータとして持たせる。

- `userPoints`: ユーザー本人が出した感想。本文から消えていないか機械検査する。
- `mustCoverTopics`: ネット調査で抽出した「作品を語るなら外せない王道ポイント」。本文に入ったか機械検査する。
- `latestInfo`: 情報基準日と根拠URL。
- `researchSources`: 公式を最低1件含む調査ソース。
- `comicCover`: 正式に利用可能なコミックス書影情報。
- `bodyImages`: 原作引用またはオリジナル画像の権利メタデータ。
- `passionChapters`: パッション章の見出し一覧。

## 公開ゲート
`rapoman/post.json` がmainへ更新されると `RAPOMAN Publish` が自動起動する。

1. `scripts/validate-rapoman.js`
   - 固定ルールを機械検査。
   - ユーザー感想の欠落、王道ポイントの欠落、最新情報の日付、根拠URL、書影、引用画像の改変、禁止項目などを確認。
   - 1件でも必須違反があればFAILして公開停止。

2. `scripts/audit-rapoman-gemini.js`
   - Geminiを執筆者とは別の独立監査役として使用。
   - ユーザーの感性が主役か、AI補完が主役を奪っていないか、普通のAIレビューになっていないか等を監査。
   - `critical` 0件かつ80点以上のみPASS。
   - FAILなら公開停止。

3. 両方PASSした場合だけ既存のはてなAtomPub投稿エンジンを実行。
   - 投稿先: `rapomarublog.hatenablog.com`
   - `rapoman/published.json` に公開済み記事を記録し二重投稿を防止。

## 一度だけ必要な設定
既存の `HATENA_API_KEY` に加え、GitHub Actions Repository secretとして `GEMINI_API_KEY` を追加する。

APIキーそのものは原稿、チャット、リポジトリへ書かない。

## 通常運用の目標
ユーザーの操作は原則2回だけ。

1. 作品名と自分の感想・語りたい点を出す。
2. 完成稿を見て「いけ」と承認する。

以降は投稿データ生成 → 2段階監査 → はてな公開 → 公開URL記録まで自動化する。
